# BGE-M3 로컬 근거 검색

선택 모델과 리비전은 `config/embedding.json`을 사용한다. 모델은 로컬에서만 불러오며 API 키·가족 프로필은 임베딩하지 않는다. 개인 조건 판정과 생성형 답변은 아직 연결하지 않았다.

프로젝트 루트 PowerShell:

```powershell
.venv-embedding\Scripts\python.exe scripts\embedding_search.py status
.venv-embedding\Scripts\python.exe scripts\embedding_search.py build --limit 32
.venv-embedding\Scripts\python.exe scripts\embedding_search.py search "출산 가정 지원" --limit 5
```

`build`에 limit을 생략하면 남은 전체 조각을 생성한다. CPU 작업이므로 오래 걸릴 수 있다. 16개마다 SQLite 트랜잭션으로 저장하고, 재실행하면 저장된 조각을 건너뛴다. 중단 시 마지막 미완료 블록만 다시 계산한다. 동시에 두 생성 작업을 실행하지 않는다.

검색 대상은 현재 버전의 설명 조각 77,560개다. `source_condition_codes` 10,898개는 원본 DB에 보존하되 의미 검색에서는 제외한다. 기존 버전은 검색하지 않는다. 입력 해시와 모델 설정 서명을 보관하며 설정이 달라지면 기존 인덱스를 혼용하지 않는다. 긴 입력은 묵시적으로 자르지 않고 오류로 중단한다.

벡터는 `data/knowledge/embeddings.sqlite`에 저장한다. 검색 결과는 cosine 유사도와 제도 ID, 조각 ID, 원문, 원문 위치, 출처 메타데이터를 반환한다. 유사도는 자격 확률이 아니다. 부분 인덱스에서도 검색은 가능하지만 coverage.complete=false를 명시한다. 전체 수집 범위와 벡터 인덱스 범위는 서로 다르다.

2026-11-27 검증: 실제 BGE-M3로 32개 조각 생성 및 출산 지원 검색 실행, 근거·출처 반환 확인. 이 표본은 기능 확인용이며 검색 품질 평가가 아니다. 전체 벡터 생성과 웹 화면 연결은 후속 작업이다. 재개·현재 버전 제한·코드 제외·설정 혼용 방지는 `test_embedding_search.py`로 검증했다.

## 전체 생성 및 웹 시험 연결

전체 생성 작업을 시작했다. `data/knowledge/embedding-progress.json`과 `embedding-build.log`에 저장 수·소요 시간을 기록한다. 77,528개 미처리 조각을 CPU에서 순차 처리한다. 초기 실측 약 1.7~2개/초로 전체 처리에 약 11~13시간이 예상되며 이후 문장 길이에 따라 달라진다. 처리 중인 PC를 종료하거나 절전하면 생성이 진행되지 않는다. 완료 여부는 저장 수와 `complete`로 판단하고, 실행 중이라는 이유만으로 완료로 표시하지 않는다.

외부 브라우저에서 `http://127.0.0.1:8765/progress`를 열면 5초마다 저장 수·속도·예상 잔여 시간이 갱신된다. 창을 닫아도 별도의 생성 프로세스는 계속된다. 저장된 블록은 재실행 시 보존한다. 프로세스가 비정상 종료되어 진행 기록이 남더라도 120초 이상 갱신이 없으면 화면에 상태 확인 필요를 표시한다.

서버 실행은 임베딩 전용 Python을 사용한다:

```powershell
.venv-embedding\Scripts\python.exe scripts\serve_catalog.py
```

`/api/embedding-status`는 전체 대비 생성 수와 작업 진행 기록을 반환한다. `/api/semantic?purpose=birth`는 BGE-M3 검색 근거를 제도별로 중복 제거하여 최대 20개 반환한다. 현재 버전 조각만 읽고, 입력 해시·벡터 차원·유한값·정규화를 검사한다. 모델은 첫 검색 때만 메모리에 불러온다. 현재 구현은 전체 벡터를 순회하는 검색이므로 데이터 증가 시 응답 시간과 메모리 사용을 재측정한다.

웹에서 지원 분야와 사용자가 입력한 검색어만 로컬 서버에 전달한다. 나이·지역·양육 상황 등 가족 답변은 전송하지 않고 브라우저에서 후보 순서를 보완한다. 키워드 일치가 없어도 의미 검색 결과는 보존한다. 서버 연결 실패 시 기존 키워드 검색으로 돌아가며 화면에서 이 사실을 명시한다. 저장·암호화 동작은 그대로 유지한다.

부분 인덱스로 검색하면 화면에 생성 수와 검색 범위 제한을 표시한다. 각 카드에서 원문 근거를 펼쳐볼 수 있다. 유사도는 자격 확률이 아니고, 과거 안내·미확인 지역 조건을 제거하는 승인 규칙은 아직 없다.

실제 HTTP 검증에서 출산 분야 검색으로 서로 다른 제도 20개와 원문·위치·출처를 반환했다. 첫 모델 로딩을 포함해 약 26초가 걸렸다. 이 결과는 `data/knowledge/web-search-verification.json`에 저장했다. 전체 인덱스 품질 검증은 생성 완료 후 해야 한다. 브라우저 제어 도구 초기화 오류로 시각 검증은 하지 못했다. 단위·HTTP·Node 검사만 통과한 상태다.

## 수집된 스냅샷의 후속 처리

`scripts/refresh_search.py`는 수집된 로컬 스냅샷을 정규화 → 조건 검토 초안 → 원문 버전·문서 분할 → 임베딩 순서로 처리한다. 새 API 호출이나 주기 실행은 하지 않는다. 실제 최신 수집은 별도로 완료해야 한다. 수집기가 완료로 표시하지 않은 필수 소스는 기존 정규화 검증에서 거절한다.

```powershell
.venv-embedding\Scripts\python.exe scripts/refresh_search.py --plan
.venv-embedding\Scripts\python.exe scripts/refresh_search.py --limit 32
.venv-embedding\Scripts\python.exe scripts/refresh_search.py
```

`--plan`은 데이터를 변경하지 않는다. limit은 이번에 처리할 미저장 조각 수이며 기존 벡터를 재사용할 수 있는 조각도 포함한다. 생략하거나 0이면 전체 미저장 조각을 처리한다. 같은 모델 설정에서 입력 SHA-256이 같은 벡터는 문서 버전·조각 ID가 달라도 재사용한다. 내용이 바뀐 입력만 계산한다. 같은 블록의 동일 입력도 한 번만 계산한다. 원문과 벡터 이력은 삭제하지 않으며 현재 문서 버전의 조각만 검색한다.

갱신과 임베딩 생성은 같은 OS 파일 잠금을 사용한다. 정상·비정상 프로세스 종료 시 잠금이 해제된다. 잠금 도입 전에 시작한 기존 생성 작업도 PID와 실제 명령·작업 폴더를 확인해 보호한다. 현재 실행 중인 최초 생성 작업은 그대로 계속되며 새 재사용 로직은 다음 생성 실행부터 적용된다. 새 작업의 진행 기록에는 generated_chunks·reused_chunks가 구분된다.

테스트에서 문서 버전이 바뀌고 두 문장 중 하나만 수정된 경우 새 모델 계산은 한 문장에만 발생했다. 이전 버전이 검색에서 제외되는 것, 중복 실행 거절, 처리 단계 순서와 실패 시 후속 단계 중단을 확인했다. 현재 실제 생성 프로세스가 실행 중인 상태에서도 갱신이 시작 전에 거절되고 기존 정규화·원문 DB가 변경되지 않는 것을 확인했다. 전체 실제 데이터 갱신은 현재 생성과 겹치므로 실행하지 않았다.
