# 공식 데이터 소스 및 검증 계획

확인일: 2026-11-26 (Asia/Seoul).

## 검증 수준

이번 작업은 공식 공개 API 문서 조사다. 인증키를 사용하는 API 호출, 응답 저장, 공고 첨부 다운로드·파싱, 전체 수집 범위와 품질 검증은 아직 수행하지 않았다. API의 존재와 문서상 기능을 수집 성공으로 표현하지 않는다.

세 카탈로그는 확인 당시 무료·이용허락범위 제한 없음으로 안내한다. 이는 첨부 문서·연결 사이트 전체에 같은 이용 조건이 적용됨을 의미하지 않는다. 각 원문의 재배포·저장 조건과 접근 정책도 확인한다. 문서상의 실시간 갱신 표기는 개별 정책 내용이 최신이라는 보장이 아니다.

중앙부처복지서비스와 LH 문서에서 인증키 인자가 확인됐다. 정부24 후보도 실제 사용 전 최신 인증 방식과 활용신청·호출 한도를 확인한다. 인증키를 문서나 Git에 기록하지 않는다. 사용자 프로필을 수집 API에 전달하지 않는다.

## 중요한 범위 차이

- LH는 전국 공통 제도 설명 자체보다 개별 공급공고를 찾는 보조 후보다. 해당 API가 모든 주거기관을 포괄하지 않는다.
- 정부24 목록에는 중앙부처 외 기관도 포함된다. 제공기관 유형만으로 적용 지역을 확정하지 않는다.
- API의 지원조건 코드나 요약 텍스트를 완전한 자격 규칙으로 간주하지 않는다. 예외·기준표·각주를 원문과 대조한다.
- 복지로와 정부24의 제도 중복은 원천 ID 매핑 및 수동 확인으로 관리한다. 두 출처가 일치한다고 독립된 검증 두 건으로 세지 않는다.
- 충돌하는 근거는 기관·적용 연도·모집 회차를 먼저 비교한다. 최신 수집 시각만으로 한 출처를 자동 채택하지 않는다.

## 실제 샘플 검증 계획 — 다음 작업

우선 제안 규모: 주거 5건·복지 5건의 제도 상세와 연결된 문서. 운영 범위·통계적 평가 규모를 뜻하지 않는다.

1. 활용 가능한 인증키·승인 상태를 비밀값 노출 없이 확인하고 목록·상세 API를 호출한다. 사용할 키가 없으면 공개 원문으로 가능한 검증부터 진행한다.
2. 원천 ID·URL·응답 형식·조회 시각·원문 해시·접근 결과를 기록한다.
3. API 필드와 공식 안내를 대조한다. 설명·선정기준·신청 방법·기준연도·기간이 실제로 있는지 확인한다.
4. HTML/PDF/표/스캔/기타 첨부를 구분한다. 파싱 가능한 표본과 실패 표본을 각각 남긴다. HWP 계열 지원은 미확정이다.
5. 조건별로 원문 위치·예외·기준표 연결을 사람이 확인한다. 정보가 부족하면 미확인으로 남긴다.
6. 정상·정보 부족·기간 만료·정정·충돌·지역 제한 사례를 만든다. 실제 표본이 없으면 합성 사례임을 명시한다.
7. 소스별 채택/보완 필요/보류를 기록한 뒤 MVP 제도 목록을 확정한다.

검증 기록 필드: 원천·원천 ID·제도/회차·공식 URL·기준일·수집일·문서 형식·필드 누락·파싱 결과·근거 위치·검토 상태·후속 조치.

완료 조건: 목록→상세→원문 연결을 재현하고, 파싱·최신성·조건 추출의 제한을 확인한다. 분석 대상 규칙에는 사람이 검토한 근거가 있어야 한다. 불완전한 제도는 검색·설명만 제공하거나 보류한다.
