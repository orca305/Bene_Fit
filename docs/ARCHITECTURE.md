# 아키텍처 및 RAG 설계 제안

작성일: 2026-11-26. 상태: 후보 비교 단계. 제품 방향과 상세 구현 선택을 구분한다.

## 데이터 처리 흐름

공식 목록·상세 수집 → 원문 스냅샷 보관 → 제도·버전·회차 정규화 → 문서 파싱 → 조건·예외·근거 추출 → 검토 → 검색 인덱스 및 승인 규칙 반영.

원문은 가공 데이터와 분리한다. 추출 결과에는 문서 ID·버전·페이지/절/표 위치를 연결한다. 규칙 변경 시 과거 분석을 덮어쓰지 않고 사용한 프로필·규칙 버전·분석 기준일을 추적한다.

## 사용자 질의 흐름

질문·최소 프로필 → 제도 후보 검색 → 유효 버전·모집 회차 선택 → 조건·예외·기준표 검색 → 근거 충분성 확인 → 승인 규칙 비교 → 추가 질문 또는 결과 설명.

- RAG는 근거를 확보하고, 규칙 비교 코드는 충족 상태를 계산한다. LLM은 문서 이해·설명을 담당한다.
- 불명확한 시점·모집 기간·사용자 조건은 임의로 채우지 않는다.
- 공개 제도 정보 조회와 개인별 분석을 구분한다. 프로필 없이도 검색할 수 있는 방향으로 설계한다.

## AURORE와 다른 개발 초점

AURORE에는 이미 단어·의미 검색, 질문 분석, 근거 기반 답변, 원문 대조가 있다. 단순 Hybrid RAG 도입을 새로운 성과로 주장하지 않는다.

1. 제도→버전→회차→조건·예외·표 연결을 이용한 계층 검색.
2. 적용 시점과 사용자 조건을 반영한 검색. 모르는 조건은 확정 제외 필터로 쓰지 않는다.
3. 문서 근거 부족은 제한된 재검색, 사용자 정보 부족은 추가 질문으로 구분.
4. 승인된 규칙에 따른 조건별 결과와 원문 위치를 함께 제공.
5. 추출·검색·규칙 비교·설명을 분리 평가.

재검색은 횟수·시간·비용 상한을 두고, 해결되지 않으면 보류한다. 상한 수치는 샘플 측정 후 정한다. 지역·기간 필터는 검증된 메타데이터에만 적용하고 미상 데이터는 미확인 경로로 처리한다.

## 기술 후보와 도입 기준

| 영역 | 후보 | 채택 전 확인 |
|---|---|---|
| 웹 | Next.js / TypeScript | 익숙한 기반 재사용. 새로운 프론트 프레임워크 도입은 현재 필요하지 않음 |
| API | FastAPI / Pydantic | Python 중심으로 수집·분석과 서비스 API를 통합할지 결정 |
| 정형 데이터 | PostgreSQL | 제도·규칙·사용자·원천 ID 매핑 |
| 검색 기준선 | pgvector + 키워드 검색 | 한국어 질의별 정답 근거 검색 품질 측정 |
| 검색 비교 후보 | Qdrant | 같은 문서·질문으로 기준선과 비교, 인덱스 동기화 비용 포함 |
| 문서 처리 | Docling | 한국어 표·각주·페이지 구조를 실제 공고에서 확인. HWP 지원 가정 금지 |
| AI 흐름 | LangGraph | 추가 질문과 재개·검토 분기가 필요할 때 적용. 단순 검색은 함수로 시작 가능 |
| 추적·평가 | Langfuse + 평가 데이터 | 추출·검색·생성 단계 추적. 개인정보 로그 제거 및 보관 정책 필요 |
| 배치 | 스크립트·스케줄 실행 → 필요 시 Celery | 장시간 처리·재시도·병렬성 요구가 확인되면 확장 |

현재 기술 후보 중 어느 것도 사용자 최종 확정으로 기록하지 않는다. 모델·임베딩·재순위 모델·스토리지·배포 방식은 미정이다. 독립 검색 서버·Graph DB·멀티 에이전트를 먼저 구축하지 않는다.

## 평가 설계

기준선과 개선안을 같은 고정 표본으로 비교하고 개발용/보류 평가용을 구분한다.

| 단계 | 평가 항목 |
|---|---|
| 파싱·추출 | 필드 정확도, 단위·연도·가구 기준, 예외·각주 누락, 근거 위치 정확도 |
| 검색 | 정답 근거 Recall@k, 순위, 만료·잘못된 회차 혼입, 프로필 필터의 잘못된 제외 |
| 조건 비교 | 네 상태의 정답률, 정보 부족을 충족으로 오판한 건수, AND/OR 및 예외 처리 |
| 답변 | 문장별 근거 충실도, 출처·기준일, 미지원 단정, 필요한 추가 질문 |
| 운영 | 응답 지연, 모델 비용, 재검색·실패·보류 비율 |

처음부터 모든 지표의 목표치를 임의로 정하지 않는다. 샘플 기준선을 측정한 후 출시 인수 기준을 정한다. 자동 LLM 평가만으로 규칙 정답을 승인하지 않는다.
