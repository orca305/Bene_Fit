# 공식 조건과 질문 연결 설계

검증일: 2026-11-27. 규칙 승인 전 초안.

## 실제 API의 세분화 수준

정부24 supportConditions는 연령 시작·종료, 소득 구간, 임신·출산·입양,
한부모/조손, 다자녀, 무주택 등의 분류 필드를 제공한다.
복지로 상세는 지원대상·선정기준 설명문 및 법령·서식 등의 연결을 제공한다.
세부 조건과 예외가 설명문에 있어도 기계 실행용 조건식인 것은 아니다.

실제 수집 데이터:
- 정부24 10,898건 중 연령 시작·종료가 함께 있는 항목: 9,904건
- 소득 5개 구간이 모두 Y인 항목: 7,732건
- 한부모/조손과 가구 해당사항없음이 동시에 Y인 항목: 7,664건
- 중앙부처 상세 88건, 지자체 상세 10건 확보. 전체 상세 수집은 미완료.

Y를 그 조건이 필수라는 뜻으로, null을 해당 대상 제외라는 뜻으로 해석하지 않는다.
한부모/조손은 하나의 원천 코드이므로 두 가족 형태를 코드만으로 분리할 수 없다.
다자녀 코드만으로 최소 자녀 수나 자녀의 연령·출생 순서를 확정할 수 없다.
원천 연령도 아이·보호자·신청자 중 누구의 나이인지 확인해야 한다.

공식 명세:
- https://www.data.go.kr/data/15113968/openapi.do
- https://www.data.go.kr/data/15090532/openapi.do

## 실행 가능한 규칙의 계약

규칙 하나에 다음을 명시한다.
- 제도 원천 ID·버전·회차·세부 지원 유형
- 기준일·적용 시작/종료·정정 및 만료 상태
- 판단 대상: 신청자 / 지원대상자 / 보호자 / 특정 가구
- 질문과 연결할 사실 키 및 단위: 예 beneficiary.age_months
- 비교 연산·경계 포함 여부·범주·공식 표 참조
- AND / OR / 예외 / 제외 / 중복 제한의 관계
- 원문·버전·필드·문장·표 위치·근거 인용
- 검토 상태와 검토시각·검토자
- 승인된 적용 범위와 미지원 계산

소득·자산은 단순 연봉과 비교하지 않는다. 제도의 가구 범위·소득 산정 방식과
검증된 기준표가 없으면 비교를 보류한다.
새로 필요한 정보가 있으면 그 조건을 확인하는 이유를 표시하고 선택 질문으로 요청한다.
건너뛰기·모름은 null/미확인으로 유지한다.

## 질문과 판정 흐름

1. 분야·검색어로 후보를 찾는다.
2. 해당 후보의 승인된 조건 목록을 조회한다.
3. 이미 답한 가족별 사실과 정확히 연결한다.
4. 부족한 사실에 해당하는 질문만 제시한다.
5. 승인된 조건을 비교하고 조건별 근거를 표시한다.

미승인·범위 불명확 규칙: 기관 확인 필요
승인된 규칙에서 사용자 정보 부족: 정보 부족
승인된 규칙과 입력값 비교 성공/실패: 확인한 조건 충족/미충족
일부 조건 충족을 전체 자격 충족으로 승격하지 않는다.
승인된 조건의 미충족만 명확한 제외 근거로 사용할 수 있다.
그 외 미확인 후보는 별도 그룹으로 남긴다.

## 이번 구현

    python scripts/build_condition_drafts.py
    python scripts/test_condition_drafts.py

data/conditions/drafts.jsonl에 16,196개 원천 레코드별 검토 초안을 생성했다.
10,183개 레코드에서 질문 검토 단서를 찾았다.
자료가 없다고 조건이 없는 제도로 간주하지 않는다.
본문 단서는 키워드가 나온 위치·발췌·원천 필드만 기록한다. 수치·필수조건·AND/OR를 자동 확정하지 않는다.
공식 코드도 원래 값만 보존한다.
모든 초안은 draft, subject unresolved, operator null, usable_for_eligibility false다.
원천 코드와 본문을 대조하기 전에는 UI 자격 필터에 반영하지 않는다.
승인 규칙은 아직 0개이며 현재 화면은 연관 후보 탐색이다.

2. 대상자·보호자·가구를 구분한 조건식을 작성하고 예외·원문 근거 검토.

4. 승인 규칙에서 필요한 질문을 생성하고 확인 수준에 따라 검색 결과 분리.
