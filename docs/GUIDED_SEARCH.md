# 선택형 가족 혜택 탐색

갱신: 2026-11-27. 현재는 질문 흐름과 관련 후보 탐색 단계이며 제도별 자격 규칙 승인 전이다.

## 사용자 흐름

1. 나·자녀·부모님·우리 가구 중 검색 대상 선택. 건너뛰기 가능.
2. 지원 목적 선택. 개인정보 없이 분야만으로 후보 탐색 가능.
3. 지역·대상자 나이 등 필요한 질문을 한 개씩 표시.
4. 모름·건너뛰기 또는 지금 정보로 후보 보기 지원.
5. 후보를 본 뒤 관련 질문에 추가 답변하거나 이전 답변 수정.
6. 사용자가 원할 때만 이번 가족의 답변을 암호화 저장.

첫 화면에는 제도 목록을 나열하지 않는다. 분야도 검색어도 없으면 전체 목록을 대신 보여주지 않는다.
소득·자산·진단명·정확한 생년월일은 현재 탐색에서 묻지 않는다.
질문별로 용도와 현재 판단의 제한을 표시한다.

## 분기

- 출산·육아: 출산 전/후, 출산 후 월령, 출생 순서·자녀 수·양육 형태.
- 한부모 양육 선택 시에만 기관 지원대상 인정 여부 질문.
- 혼인 상태만으로 한부모 지원대상이라고 판단하지 않는다.
- 부모님 생활·돌봄: 부모님 나이·동거 상황·필요한 도움.
- 보호자의 나이·소득을 자녀나 부모님에게 자동 적용하지 않는다.
- 가구 판정은 미구현이며 함께 산다고 같은 소득 산정 가구로 처리하지 않는다.

### 분야별 선택 질문 보완

기본 가족 탐색과 출산·육아/부모님 질문은 기존 구현이다. 아래 분야를 추가하고 대상 구분을 보완했다. 모든 질문은 건너뛸 수 있다.

| 분야 | 추가 질문 | 답변의 대상 |
|---|---|---|
| 주거 | 월세·보증금·공공임대·집수리 등 필요한 지원, 현재 거주 형태 | 지원 목적 / 지원받을 개인 또는 가구 |
| 생활비 | 일상 생활비·에너지·긴급 지원·요금 감면 | 지원 목적 |
| 취업·창업 | 구직·훈련·창업·사업 운영, 현재 활동 상황 | 지원 목적 / 지원받을 개인 |
| 건강·의료 | 의료비·검진·재활·간병 | 지원 목적 |
| 교육·장학 | 교육 단계, 학비·장학금·학습비·평생교육 | 지원받을 학습자 / 지원 목적 |

지역·나이 질문에는 본인/대상 자녀/대상 부모님을 명시한다. 우리 가구를 선택하면 개인의 나이·취업 상태·교육 단계·부모 동거 질문을 묻지 않고, 저장값에서도 이를 제거한다. 개인별 비교가 필요하면 해당 가족으로 별도 탐색해야 한다. 분야를 아직 선택하지 않았을 때도 나이를 먼저 묻지 않는다.

주거 형태를 무주택 여부로, 활동 상황을 고용보험 가입 여부로, 교육 단계를 장학금 자격으로 바꾸어 해석하지 않는다. 현재 거주 형태·활동 상황·교육 단계는 향후 승인 규칙에 연결할 답변이며 아직 자동 비교하지 않는다.

세부 지원 목적은 공개 설명의 관련 단어와 비교해 브라우저 내 후보 순서를 보완한다. 문장 내 예외·제외 표현을 해석하는 자격 규칙이 아니므로 결과를 배제하지 않는다. 소득·자산·정확한 생년월일·진단명·학교명·성적은 추가 수집하지 않는다. 단계가 출산 전으로 변경되면 아이 월령, 한부모 양육이 아니면 지원대상 인정 여부, 분야가 달라지면 다른 분야의 답변을 정리한다. 기존 저장값에 출산 단계 없이 월령이 있는 경우 단계가 확인될 때까지 보존하며 출산 전을 선택하면 제거한다.

## 데이터 및 자격 결과

공개 카탈로그만 서버에서 읽고 검색어·지원 분야만 로컬 의미 검색 서버로 보낸다. 나이·지역·세부 지원 목적·가족 답변과 암호는 전송하지 않는다. 벡터가 없거나 검색 서버가 실패하면 키워드 방식으로 표시하고 화면에 이를 명시한다.
관심 분야·검색어와 안내 내용의 관련성으로 후보를 정렬한다.
미응답은 조건 미충족이 아니며 모든 결과의 자격 상태는 확인 필요다.
관련 안내를 찾은 사실을 자격 충족으로 표현하지 않는다.
월령·출생 순서·자녀 수·한부모 인정·동거 상황 등은 질문 답변으로 보관하지만 승인된 제도별 조건 계산에는 아직 연결하지 않았다.
실제 자격 비교를 위해서는 공식 조건·예외·기간·근거·검토 상태를 갖는 규칙 데이터가 필요하다.
후보별 질문 버튼은 현재 동일 분야의 추가 질문으로 이어지며 검증된 개별 제도 규칙에 의해 생성된 질문은 아니다.

## 가족 정보 저장

새 탐색은 기본적으로 메모리에서만 진행한다. 저장하지 않으면 새로고침·페이지 이동 시 소실된다.
저장 버튼을 선택했을 때만 보관 암호를 요구한다.
같은 BFVault AES-GCM/PBKDF2 구현을 사용하며 sessionStorage 또는 명시적 선택 시 localStorage에 암호문만 기록한다.
가족별 고유 ID로 자녀·부모 등 답변을 분리한다. 이름은 받지 않는다.
암호화 저장된 기존 가족이 있으면 먼저 불러오도록 해 덮어쓰기 손실을 막는다.
저장한 가족 목록에서 대상 선택·수정·추가, 암호화 가족 정보 전체 삭제를 지원한다.
이전 단일 프로필 저장소는 가족 탐색에 자동 적용하지 않는다.
