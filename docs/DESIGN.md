# Bene_Fit 설계 v0.2

작성일: 2026-11-26 (Asia/Seoul). 상태: 사용자 합의 방향 + 상세 설계 제안.

## 합의된 방향

- Bene_Fit / BF(Best Friend): 개인 맞춤형 생활 혜택 플랫폼.
- 초기 분야는 주거와 복지. 전국 공통 제도를 우선하고 지역별 혜택은 이후 확장한다.
- 서비스 대상은 전국 사용자. 초기 테스터는 대전 지인 중심이다.
- 일반 사용자에게 유용한 서비스와 LLM·Advanced RAG 학습을 함께 지향한다.
- 현재는 설계 단계이며 구현은 시작하지 않는다.

## 범위 해석 제안

전국 공통 제도는 전국 누구나 무조건 신청할 수 있다는 뜻이 아니다. 대상 조건과 집행 지역이 있을 수 있다. 중앙기관이 운영하는 지역 한정 공고도 전국 공통으로 자동 분류하지 않는다.

1차에는 전국 단위 주거·복지 제도의 탐색과 공식 조건 설명을 제공한다. 임대주택처럼 실제 신청이 개별 공고에 의존하면 검증된 모집 회차에 한해 일정·조건을 안내한다. 전국 모든 기관과 모집공고를 수집했다고 표현하지 않는다.

지역 고유 사업은 후속 범위다. 주거급여처럼 지역별 기준이 있는 전국 제도는 지역 차이를 보존한다. 초기 대상 연령·직업을 청년이나 직장인으로 제한하지 않는다.

## MVP 요구사항 제안

| ID | 요구사항 | 인수 기준 |
|---|---|---|
| BF-001 | 주거·복지 검색 및 필터 | 분야·적용 지역·기준일로 조회하고 수집 범위를 표시한다. 기간 미확인을 모집 중으로 표시하지 않는다. |
| BF-002 | 제도 상세 | 지원 내용·대상·신청 방법·출처·확인일을 표시한다. 누락 항목은 미확인으로 표시한다. |
| BF-003 | 최소 프로필 | 지역·나이·가구 형태·주거 상태 등을 필요할 때 질문하고 수정·건너뛰기를 지원한다. |
| BF-004 | 맞춤 후보 추천 | 추천 이유와 미확인 조건을 제공한다. 모르는 조건 때문에 후보를 확정 제외하지 않는다. |
| BF-005 | 제한된 조건 분석 | 검증된 규칙에 한해 충족/미충족/정보 부족/기관 확인 필요를 반환하고 조건별 근거를 연결한다. |
| BF-006 | 근거 기반 상담 | 제도→버전→모집 회차→관련 조항을 탐색한다. 필요한 근거가 없으면 재검색 또는 답변 보류한다. |
| BF-007 | 추가 질문 | 문서 근거 부족과 사용자 정보 부족을 구분한다. 후자는 필요한 항목만 질문한다. |
| BF-008 | 신청 안내 | 확인된 서류·기간·공식 신청처를 제공한다. 제도 설명을 현재 접수 공고로 오인시키지 않는다. |

기능별 개발 순서: 검색·상세·근거 제공 → 프로필·추천 → 검증된 일부 규칙 분석.

관심 저장·비교·알림·중복 수혜 분석·지역 사업·민간 혜택·AURORE 연계는 후속이다. 자동·대리 신청은 초기 범위에 포함하지 않는다.

## 데이터·판단 원칙

- 제도, 정책 버전, 모집 회차, 원문 문서, 조건 규칙과 근거를 구분한다.
- 시행일·공고일·접수 기간·원천 수정일·수집일·검증일을 별도로 기록한다.
- 기관과 제도명이 같다는 이유만으로 데이터를 자동 병합하지 않는다. 원천 ID를 보존한다.
- 연봉을 제도별 소득인정액으로 간주하지 않는다. 자동 계산 범위는 별도 설계한다.
- LLM 추출은 후보 데이터다. 검토·승인되지 않은 규칙으로 충족/미충족을 확정하지 않는다.
- 주민등록번호는 수집하지 않는 방향으로 설계한다. 소득·자산 등은 필요 시 최소한으로 요청한다.
- 인증·프로필 보관 기간·삭제·외부 모델 전달 범위는 미정이다. 실제 개인정보 수집 전 구체화한다.

## 미정

최초 제도 목록, 운영에 사용할 데이터 소스, 인증, 배포 환경, 예산, 모델, 기술 스택, 수집 주기, 성능·품질 목표. 수치 목표는 샘플 평가 후 정한다.
